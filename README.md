# 职野 Career Atlas

给正在选择专业、找第一份工作或考虑转行的人使用的中文职业探索工作台。首页可以直接翻阅图鉴，也可以从个人画像开始。全站使用原创罗盘、山野版画和职业工具插画，主色为林绿和鼠尾草绿。

## 产品设计

| 用户要解决的问题 | 在应用中的操作 | 得到的结果 |
| --- | --- | --- |
| 我喜欢的是这个职业的名字，还是它每天要做的事？ | 阅读工作实景，选择自己愿意接手的情境任务 | 了解任务分工、工作收获与压力，以及自己想尝试的部分 |
| 哪些方向值得先了解？ | 选择活动兴趣、工作条件和现有技能 | 按选择项的重合程度排序，可逐项查看匹配依据 |
| 哪些岗位条件会影响我的生活？ | 收藏两个职业后并排对比 | 一起看强度、地理体验、市场、AI 影响和起步练习 |
| 我怎样核实所在城市的工作机会？ | 打开注明地区和日期的来源，记录本地招聘样本和从业者访谈 | 按职业和城市整理工作地点、工时、薪酬、经验要求与原文 |
| 我可以做什么来验证选择？ | 在成长路径中选择一个可完成的任务，把体验存入手记 | 留下真实的耗时、困难和收获，回看哪些活动值得继续 |

## 城市资料与职业目录

职业图鉴提供深度档案和职业名称索引。深度档案可按领域和本地资料筛选，职业名称索引可按官方职业编码、名称和大类检索。北京、上海、广州、深圳、南京和成都各有独立资料页，同一份档案也能切换城市，查看有关这个职业的当地材料。

「专业与兴趣」从教育技术、短视频、穿搭与美妆、做饭与美食进入职业档案，并提供一项可试做的任务。填写画像后，各方向内会按工作偏好排序。

「真实招聘」可以组合筛选职业、工作城市和教师任教学段。默认查看已确认处于报名期的岗位。切换报名状态可查即将报名、待核实或已截止的记录。南京教师年度关注页按公告注明的招聘年度归集新批次，同时保留往年已截止的岗位表作为备考参考。职位页标明雇主、原始公告、核对日期和已知截止日，支持将原文与岗位要求带入手记。

资料页把招聘批次、岗位数量、执业要求和调研出处留在原文语境中。保存城市资料到手记时，会一并带入来源及城市。

## 资料与匹配口径

每份职业档案包含代表性任务、收获、困难、强度、地点、AI 影响、招聘市场证据、一组起步练习和一道可重选的情境题。市场章节优先提供与岗位相关的中国内地或香港资料，海外职业资料会显示所属地区。点击「调研依据」可阅读原文及其支持的具体判断。职业名称在不同地区存在差异时，档案会说明参照的职类。

匹配分是个人所选兴趣、条件和技能中，在档案中找到依据的比例。各项等权。阶段和城市用于建立调研背景，目标城市会带入招聘样本与手记。情境题单独给出这一项任务的反馈。对具体团队的工作强度、招聘人数和实际待遇，可通过手记补充带时间地点的样本。

## 运行

使用 Node.js 22 或更新版本，在项目目录执行以下命令。

```sh
npm run dev
```

默认地址为 `http://127.0.0.1:5173/`。项目无运行时第三方依赖。`npm start` 也会启动同一服务。需要其他端口时可运行 `npm run dev -- --port 5175`。

`npm run build` 会生成可放在普通静态服务器上的站点。使用 Node 服务可通过 `POST /api/collect` 读取资料库内的公开 HTML 页面摘要。静态部署保留档案、画像、比较、报告链接及手动摘录，在线采集需要 Node 服务。

## 数据与保存位置

- `data/catalog.mjs` 汇总职业与来源，按岗位关联各城证据。`data/occupation-index.mjs` 保存官方职业索引快照，`tools/import_occupation_index.py` 用于重新导入。
- 网页采集保存来源标题、正文摘录、最终链接和采集时间。原站提供发布日期时一并保留。PDF 可直接阅读原报告，访问受限时可以保存已有来源说明。
- 画像、收藏、情境选择与手记由当前浏览器保存在本机。手记可以导出 JSON 备份。在线摘要采集只向服务端提交所选来源的公开链接。

## 招聘公告日更

在装有 Python 3.10 或更高版本的机器上运行 `npm run jobs:update`。日常更新使用 Python 标准库，可独立于浏览器和 AI 服务运行。

- 在 Windows PowerShell 中执行 `.\tools\install-recruitment-task.ps1` 可注册当前用户的每日任务，时间为本机 08:30。任务在用户已登录时运行，启用错过时补跑。加 `-Remove` 可取消该工作区的任务。
- 南京学校和教育部门的栏目在 `data/nanjing-recruit-sources.json`，其它公开渠道在 `data/general-recruit-sources.json`，直接复查的教师招聘原文在 `data/teacher-recruit-pages.json`。新增来源时需核对栏目、详情链接、所属机构和工作地点。
- 更新器检查 robots.txt、按域名限速、缓存网页并按原文链接去重。默认每次每源读取最多 10 条详情，已收录公告会轮流复查。可用 `python -X utf8 tools/update_recruitment.py --limit 5` 调整每源上限。
- 来源失败时保留该来源之前的公告和读取日期。`data/recruitment-feed.mjs` 是网站读取的快照，已有本地构建时也会同步到 dist。部署在其它主机上的静态网站需同步该文件。Windows 计划运行的日志写在 `.cache/recruitment/last-run.log`。

## GitHub Pages 部署

在仓库的 Settings → Pages → Build and deployment 中选择 GitHub Actions。向 `main` 推送后，Publish Career Atlas 工作流会检查数据、构建 `dist` 并发布。成功运行的 `github-pages` 环境会显示网站地址，项目站点使用 `https://<GitHub用户名>.github.io/<仓库名>/`。

每天北京时间 08:30，GitHub Actions 会运行招聘采集脚本，将更新后的快照提交到 `main` 并重新发布。也可以在 Actions 中手动运行，勾选 “Check recruitment sources before publishing” 即可立即检查来源。开展本地改动前先运行 `git pull --ff-only` 获取已发布的快照。

Pages 版支持职业图鉴、画像、招聘筛选、来源原文和手动手记。按需读取网页正文的 `/api/collect` 接口由本地 Node 服务提供。
